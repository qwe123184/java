# 变更说明（2026-11-06）

本期修复了「一键启动（start-all.bat）后后端 8081 永远起不来」的问题，并把前后端访问地址统一到局域网 IP `192.168.68.44`。

---

## 一、根因：克隆后 Maven 缺 jar，后端构建必失败

**现象**：每次重新拉取/同步项目后，`start-all.bat` 跑完显示
`Frontend 5173: YES / Backend 8081: NO / MySQL 3306: YES`。

**根因链**：
1. 仓库 `.gitignore` 有全局 `*.jar` 规则，但“忽略 Maven 发行包”只写了 `springBootTest/tools/`，**漏掉 `java-main/tools/`**；
2. 于是 git 只入库了 Maven 的文本文件（`mvn.cmd`、LICENSE 等），**48 个 `.jar` 被静默排除**；
3. 克隆出的 Maven 看起来存在、实际已残废 → `start-all.bat` 检测到 `mvn.cmd` 就跳过下载 → 构建报
   `Error: -classpath requires class path specification` → jar 永远不生成 → 后端窗口直接退出。

**修复**：
- `.gitignore`：新增 `java-main/tools/`，让未来克隆走“自动下载 + 自检”路径；
- `start-all.bat`：新增 `:TEST_MVN`，所有 Maven 候选先跑 `mvn -v` 验证，损坏的安装自动跳过并继续搜索/重新下载。

---

## 二、功能：前后端改用局域网 IP 192.168.68.44

本机当前局域网 IP 为 `192.168.68.44`，便于同一局域网内其它设备（手机/其它电脑）访问。

**改动点**：
| 文件 | 改动 |
|---|---|
| `zhanshen/vite.config.js` | Vite 代理目标 `localhost:8081` → `192.168.68.44:8081` |
| `start-all.bat` | 控制台打印、自动打开浏览器、状态检测的地址 `localhost:xxxx` → `192.168.68.44:xxxx` |
| `start-frontend.bat` | `no_proxy` 增加 `192.168.68.44` |
| `start-backend.bat` | `no_proxy` 增加 `192.168.68.44` |
| `springBootTest/.../application-dev.properties` | 更新 CORS 示例注释（数据库 `127.0.0.1:3306` **保持不变**，那是连库地址，不能改） |

**重要说明**：
- 后端默认监听 `0.0.0.0`（所有网卡），**本来就已包含 192.168.68.44**，无需设置 `server.address`；若强行绑死 `192.168.68.44`，会导致回环地址失效并破坏启动脚本里的健康检查。
- **必须重启前端** 才能使新的代理目标生效（Vite 启动时读取配置）。后端无需改动。

---

## 三、顺手修复的启动隐患

- `start-frontend.bat` 中 Node 路径硬编码为 `22.22.2-3`（实际只有 `22.22.2-2`），之前能跑纯靠“系统 Node 兜底”。已改为**动态查找** `versions` 目录下的 Node，不再依赖写死版本。
- 在三处启动脚本的 `no_proxy` 中加入 `192.168.68.44`，避免本机若设置了 HTTP 代理时局域网 IP 被代理拦截。

- 经 `http://192.168.68.44:5173/api/...` 代理到后端 `192.168.68.44:8081` 链路已通；

- 上述修改已提交并推送到 `github.com/qwe123184/java`（提交 `2eed126`，连同 Maven 修复 `c36ad52`）。

## 五、后续注意事项

1. **IP 是写死的**：`192.168.68.44` 若因 DHCP 变化，需同步更新 `vite.config.js` 的代理目标与启动脚本里的地址；更稳健的做法是改用环境变量注入。
2. **防火墙**：首次用其它设备访问，需放行 Windows 防火墙的 5173 / 8081 入站规则。
3. **数据库**：保持本地 MySQL 在 `127.0.0.1:3306`，账号 `root`，密码 `123456`（或环境变量 `DB_PASSWORD`）。
